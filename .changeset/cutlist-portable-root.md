The catalog no longer records the machine it was built on, so `cutlist build --check` agrees
across checkouts.

`buildCatalog` wrote the absolute path it crawled from into the catalog's `root`, and `root` is
inside the hash that `--check` compares and every other rendering prints ("Generated by cutlist
from …"). The exemplar's committed catalog carried `/Users/togmund/autotelic/tackle/examples/self`,
so it was current on that machine and stale on every other one with no change to the tree, and
`jig check` failed on `cutlist/stale-catalog` for anyone else. CI did not see it, because CI runs
`pnpm check` and not the staleness gate.

`root` is now always `.`: the directory every part path is already relative to. The field stays,
and stays required, because readers decode it and the lexicon rule forbids invalidating a record
that was valid; the protocol type and the JSON Schema now describe it. The exemplar's catalog is
regenerated, which changes only `root` and the hash.
