The room and its sessions

tackle · one project · one long-lived room · many isolated workers · Oct 2026

A labeled PR is enough. The room watches the project, not your mentions; a PR by Ed carrying the project's label wakes it, the room queues a worker, the worker gets a worktree, a port, and a database, runs the branch, and posts one review. You can close the laptop; the room stays warm. What follows is the flow, the session topology, and what is actually built.

1 · The ambient loop

The trigger changes from “someone requested my review” to “a PR in this project exists and I did not write it.” That is the ambient version: pull_request.opened or labeled, the label matches the room's project, the author is not the room's actor. Dedupe is still pr:<n>:<sha>, and the review marker is still checked before posting. No mention is required.

Event Acts when Why
pull_request.opened the label is already on it, author ≠ actor Ed opens a PR ready for a first pass
pull_request.labeled the added label is the project's a draft becomes work, or the label arrives later
pull_request.ready_for_review the label is present the draft gate lifts
synchronize never on its own a push is not a request; a person or a thread asks
issue_comment / review thread a blocker on your PR a changeset, not a new review

2 · Sessions on the machine

The project session is the one you talk to. It does not own the room and it does not have to be open. It can spawn a worker, attach to one, or ask one a question. The room owns the ledger and the board. roomd is the supervisor: it claims jobs, allocates a worktree and a port, spawns the worker, watches it, and writes the receipts. A worker is a Pi session with a repo checkout, an isolated app instance, and one job.

Pi Intercom is the right local transport between these sessions: a broker, named sessions, send and ask, messages that can trigger a turn or wait for one. It is not the ledger — a message is not a receipt. Rat King is the same idea across machines, with signed mail, leases, and durable receipts; it is what Ed's laptop uses when it joins.

Piece Owns Not its job
project session the conversation, spawning, attaching claims, dedupe, the board
room (DO) jobs, claims, receipts, presence running code, holding keys
roomd slots, worktrees, ports, child lifecycle deciding what work exists
worker one checkout, one app, one transcript talking to GitHub without the room's fence
Pi Intercom 1:1 messages between live sessions durability, receipts, cross-machine
Rat King the same, signed and durable, across hosts v0

3 · One worker, one environment

Every worker gets its own git worktree at the PR head SHA, its own port from a reserved range, its own database (a schema or a SQLite file), and its own env namespace. The main checkout is never touched. The app comes up from the PR's own tree, so a review can open the page it is reviewing; the environment is torn down on exit, and a crashed worker leaves a quarantined worktree and a kept transcript rather than a half-live server.

This is the local, boring version of an Orb or a Rivet actor: an Orb is a prepared snapshot plus setup/resume; an actor is a stateful isolate with an identity. Here the identity is the room's job, the snapshot is the worktree, the isolate is the port/database pair, and the supervisor is roomd.

4 · The room outlives the session

This is already true in the built version: celld keeps the Durable Object across a Pi exit, a queued job survives, and reopening the session replays the board. What is not built yet is the worker-session supervisor and the per-session app environment; the review path exists, the spawn/attach/monitor path is the next layer.

The sentence to keep: the label is the address, the room is the memory, the worker is the hands, and the project session is where a person steers.

5 · Build order for this layer

# Move Done when
1 label trigger + author ≠ actor + dedupe by sha Ed's labeled PR queues without a review request
2 worker record: worktree, port, db, session id, transcript room board shows the worker and its URL
3 supervisor: allocate, spawn, heartbeat, quarantine kill the worker → orphaned, transcript kept, port freed
4 room attach + Pi Intercom ask a running worker a question from the project session
5 Rat King transport Ed's worker joins the same room from another machine

The current build proves the room, the board, the webhook dedupe, the claim, and the Pi widget. It does not yet spawn a worker per job; that is the next slice, and the label trigger is the first line of it.
